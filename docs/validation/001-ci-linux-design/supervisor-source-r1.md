# Supervisor implementation: source-only review scope

`linux-diagnostic.py` implements the finite protocol from the approved `proposal.md`/`review-r1.md`. It has been authored as text only: no import, syntax execution, tests, local/Linux invocation, overlay application, workflow edit, commit or push. Original design artifacts and live six-source preimages are frozen unchanged. `supervisor-freeze-r1.json` adds the executable artifact and this note to the reviewed inventory. The original proposal's statement that no supervisor is supplied remains historical to design R1; this new artifact supersedes that statement only, not its approval boundary.

The script is guarded for Linux/GitHub Actions/job verify/root cwd, existing localhost:5432/loom_test PostgreSQL URL, Bun1.4.2 and Node24. It only adds the stage directory to test environments. Suspicious ambient runtime override variables fail preflight without printing values. It does not install dependencies, start services, alter global configuration or reset the database. It does not run the original CI gates itself: the separately proposed workflow still retains them unchanged and calls this only after integration failure.

It backs up and hashes six source files and complete canonical dist, applies seven exact frozen overlays, builds once, then runs the two exact selected cases sequentially. Numeric /proc identity snapshots, start ticks and pidfds protect targeted cleanup from PID reuse; subreaper adoption covers descendants that outlive their direct parent. Observations are sampled at approximately50ms: peakObservedProcesses is a lower bound and fast births may be missed. Missing observed provisioning PIDs makes trace evidence incomplete. It never interprets cumulative observed births as peak simultaneous workers.

Additional fail-closed bounds:256 retained process identities per command,4096 supervisor-event ceiling with terminal receipt reserve,20,000 dist entries with a1MiB serialized manifest ceiling,128MiB per backed-up dist file,64trace files/8MiB aggregate,1MiB each/4096-byte records,8MiB private console per command. Limits are diagnostic ownership guards, not test timeout/assertion changes. No retry loop or extra selected test is added. A version command has10s supervisory ceiling, build180s, dev120s, provision30s; original test deadlines remain unchanged.

Console data stays only under private/, never uploaded. JSONL upload is reconstructed from a strict closed field/stage/type validator; a malformed/truncated record stops its file's validated prefix and marks evidence incomplete. Full console counts are parsed without copying assertions. Missing child/fixture cleanup or forced termination cannot become successful evidence. The supervisor journal and final report contain only static labels, numeric identity/timing/exit data, approved hashes and bounded version/config metadata. Exact reporter/runtime introspection remains unavailable: argv and config presence/hashes are reported, no fabricated resolved reporter or Vitest-to-Bun worker inference.

Restoration normally runs in finally, including red tests. If owned cleanup fails or a direct child remains, restoration is withheld to avoid changing source/dist beneath live code; the receipt says incomplete/restored:false, preserves backups and remaining numeric identities, stops dependent cases, and leaves the disposable GitHub job teardown to dispose of its service/processes. No foreign termination or DB reset is attempted. SIGTERM/SIGINT requests owned cleanup/restoration; SIGKILL, runner loss or filesystem failure may prevent the final receipt/upload, which is not accepted evidence. Artifact upload must independently succeed after the script; no receipt claims it already did.

Sources consulted read-only for configuration semantics: official Bun docs https://bun.sh/docs/runtime/bunfig and https://bun.sh/docs/test/configuration. Current docs distinguish local runtime/test configuration from global package-manager configuration; they are not pinned1.4.2 runtime introspection. Supervisor conservatively hashes discovered local/home/XDG config, permits only install settings plus an empty test table, and rejects runtime/test overrides without publishing values. Global test applicability is explicitly not assumed. This uncertainty remains a limitation for the reviewer.

Fresh review must carry the original two0dbb CI integration reds, earlier142 startup reds, three-case macOS nonreproduction with absent console stages, resource-policy-only approval, sole Luna findings, original design R1 approval/limits and previous implementation privacy/watcher/strict-shutdown findings. Approval of this source is not execution authorization or a demonstrated CI fix.
