## Development coordination and watching (U8, partial)

The coordinator invalidates a running revision immediately when a newer edit arrives, debounces the next update, and retains exclusive pipeline ownership until the previous update and its cleanup settle. Each update receives an abort signal and a revision guard for use under the database/publication lock. Failed revisions are recorded without preventing a later edit from recovering. Stopping cancels queued work, aborts active work and waits for cleanup. The watcher observes the project tree, including imported helpers outside the function directory, and excludes Loom state, generated outputs, dependency directories and build outputs. ## Function transaction execution (U9, partial)

The runtime transaction primitive uses read-only repeatable-read transactions for queries and serializable transactions for mutations. It retries the entire callback only for PostgreSQL serialization failures and deadlocks, including errors wrapped by Drizzle. Attempts are bounded (three by default, configurable from one through ten), with capped exponential delay and abort checks before entry, after session acquisition and before commit. Abort during retry delay stops further attempts. Callbacks must not perform external effects; this API does not sandbox application code or cancel an already-running SQL statement.
