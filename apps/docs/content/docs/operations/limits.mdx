## Verification baseline

The native oRPC runtime has PostgreSQL 18 integration coverage, browser coverage and packed consumer checks. Real Neon acceptance has exercised Auth, Functions, Object Storage events and durable processing. The repository's `docs/architecture/orpc-execution.md` records which runtime each receipt tested and which changes still require hosted verification.

Final native acceptance passed three spread and three hot-table runs: 100 subscriptions across two Functions and ten committed writes per second for ten minutes after warmup. Notification-mode live-update p95 was 269–378 ms, 68–79% below the matched polling baseline. All finite-RPC, typecheck, bundle and resource gates passed. The repository's `docs/architecture/orpc-acceptance.md` records distributions and measurement limits, including baseline runs taken several hours earlier. There is no production performance SLA.

Local tests cover process interruption, reconnect, lease recovery and a non-reading TCP client. Hosted tests also exercise capacity refusal and listener recovery. Account-wide WebSocket quotas, provider eviction guarantees and billed workload cost remain unmeasured.

## Runtime bounds

Realtime defaults to polling every 1,000 milliseconds. Notification mode adds one direct database listener per active runtime, shared by its subscriptions; polling remains the recovery path. Reevaluations run with concurrency four. The default runtime limit is 100 subscriptions, configurable from 1 to 1,000; this is an admission limit, not a throughput guarantee.

Socket sessions bound messages and buffered output to 1 MiB by default, with at most 64 concurrent calls and 200 inbound messages per second. Oversized traffic closes with `CAPACITY_EXCEEDED`; a full output buffer closes with `RESYNC_REQUIRED`. Neon maps reserved server close codes to application codes: 1009 becomes 4009 and 1013 becomes 4013. Clients should retain the reason when reporting these failures.

## Credentials and test targets

Local database tests require an explicit `LOOM_TEST_DATABASE_URL`. Required hosted checks run through `bun run test:cloud` with `LOOM_CLOUD_SUITE`, `LOOM_CLOUD_PROJECT_ID`, `LOOM_CLOUD_BRANCH_ID` and `NEON_API_KEY`. The runner rejects default or protected branches and requires the `loom-acceptance-` name prefix. The Auth suites also require the branch Auth URL or explicit acceptance Auth setup. Missing prerequisites fail the required runner; skipped opt-in test files are not acceptance evidence.

## Retiring a runtime

Database retirement checks activation identity, ingress retirement, pending jobs, and live client sessions before retiring database authority. It retains historical artifacts. This does not stop every provider process or drain external action side effects across instances.

## Package availability

Packages remain private in this workspace. Public registry identity, licensing and release publication must be settled before a public installation guide can promise a supported release.
