## Verification baseline

The repository has local PostgreSQL 18 integration coverage, browser coverage and packed consumer checks. Both example applications have passed real Neon acceptance: authenticated tasks and live subscriptions, and authorized uploads with Object Storage events and durable processing.

Short Neon bursts with 1, 4 and 8 writers and browser pages completed 3/3, 11/12 and 19/24 writes in the final measurement. Rejected writes returned HTTP 409 `TRANSACTION_CONFLICT` after bounded retries and left no rows; successful writes reached every page. These results do not establish reliable burst capacity. HTTP client retries were disabled for this measurement.

Local tests kill an API process and a worker, verify reconnect and lease recovery, and exercise a non-reading TCP client through bounded socket buffering and deterministic resync. Provider eviction, whole-isolate memory, sustained throughput, account-wide WebSocket quota accounting and billed workload cost remain unmeasured. There is no production performance SLA.

## Credentials and test targets

Local database tests require an explicit `LOOM_TEST_DATABASE_URL`. The cloud database test requires both `LOOM_CLOUD_PROJECT_ID` and `LOOM_CLOUD_BRANCH_ID` and refuses a default or protected branch. Use a disposable acceptance branch; never point destructive integration tests at application data.

## Retiring a runtime

Database retirement checks activation identity, ingress retirement, pending jobs, and live client sessions before retiring database authority. It retains historical artifacts. This does not stop every provider process or drain external action side effects across instances.

## Package availability

Packages remain private in this workspace. Public registry identity, licensing and release publication must be settled before a public installation guide can promise a supported release.
