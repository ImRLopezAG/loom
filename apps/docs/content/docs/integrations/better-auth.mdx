<Steps>
<Step>
### Define the server once

Use `defineBetterAuth` with a deterministic `create({ env, database })` factory. Pass the supplied database adapter to native `betterAuth`. Mount the component explicitly with `app.use`. The [server setup guide](/authoring/better-auth) shows the full declaration.

</Step>
<Step>
### Plan plugin schema changes

Add native server plugins to that factory. Generate and review migrations before deploying. Core tables and plugin tables live in the component namespace. Changing a plugin, model name, additional field, or ID setting can change the schema. Do not manually duplicate generated plugin tables in application code.

</Step>
<Step>
### Keep native routes and client plugins

Use Better Auth's client pointed at the mounted auth URL, with the client counterparts required by your selected plugins. Plugins can contribute tables, endpoints, and browser methods together. Loom forwards the native handler; it does not translate each plugin endpoint into RPC.

</Step>
<Step>
### Bridge access tokens

The native JWT plugin issues a JWT and exposes public verification keys through JWKS. Configure Loom to trust that issuer and audience. Adapt the native client's session state and token method to `LoomProviderAuth`; session cookies themselves are not Loom access tokens. See [Better Auth JWT](https://better-auth.com/docs/plugins/jwt).

</Step>
</Steps>

<Callout title="Managed Neon Auth is a different integration">
  Neon's hosted service owns its Better Auth configuration. Installing a custom plugin in your local client does not
  install it on that managed service. Use a customer-owned server when you need custom server plugins.
</Callout>

Test each chosen combination through schema planning, migration, endpoint calls, token validation, sign-out, and client methods. The current hosted cookie-delivery limitation is recorded in [authentication](/authoring/auth). Native bearer/JWT results do not establish acceptance for every cookie-dependent OAuth flow. Better Inbox remains a test example, not a required package.

For plugin authoring, use [Better Auth's server and client plugin guide](https://better-auth.com/docs/concepts/plugins). Keep application-defined plugins in your application or a component package; Loom does not need a wrapper package for every SDK.
