## Define a procedure

Import `procedure` from `loom/_generated/server`. Export public procedures below `loom/functions/` and server-only procedures below `loom/internal/`. Modules can also export an explicit `router` or default router. Helpers stay outside the generated route graph. Internal procedures are absent from the public client and transports.

<Snippet code={functionsSource} />

These are native oRPC procedures: use `.input`, `.output`, `.use`, `.errors`, `.handler`, and `.effect` with upstream inference. Generation binds your schema and Drizzle relations once. Every handler receives typed `tables` and `validators` in `context`; database middleware adds `db`.

Inputs are optional. Without `.input`, call the method without an input value. Handler returns infer client types; `.output` adds runtime validation and can project private columns out of a response. For example, the create handler above supplies ownership on the server and returns only its declared public fields. Runtime output validation and native serialization finish before a database write commits.

Precise OpenAPI generation requires explicit output schemas for public procedures. Set `openapi: true` in `loom.config.ts` to expose the validated finite REST graph. Inferred TypeScript return types alone cannot supply runtime OpenAPI schemas.

## Client presentation and database authority

`clientMode("finite")`, `clientMode("live")`, and `clientMode("mutation")` determine the generated TanStack options. The default is mutation. This metadata does not grant database permissions or make a side effect safe to repeat.

Use `.use(databaseRead)` for a read-only repeatable-read transaction. Use `.use(databaseWrite)` for a serializable transaction with bounded retries for serialization failures and deadlocks. A bare procedure has no database authority. A live procedure requires database-read authority so each reevaluation captures a consistent result and table revisions.

The database rejects writes in a read transaction. It cannot detect an email or payment performed by your JavaScript. Keep external effects out of retryable database handlers; schedule an internal procedure transactionally and use the job ID for external idempotency when the provider supports it.

## IDs and authorization

Use `validators.id("tasks")` or `schema.id("tasks")` to validate UUID syntax and infer `Id<"tasks">`. IDs do not prove table membership, existence, or access. Check the row and ownership inside the transaction; schema references supply database foreign keys.

Filter by verified issuer and subject, plus your tenant policy. Do not accept an owner ID supplied by the caller as authorization. A missing or inaccessible row must not be accepted merely because its ID is well-formed.

## Effect and invocation lifetime

`.effect(function* (...) { ... })` uses the shared Effect runtime. Generated `Database`, `Tables`, and `Validators` services preserve project types; `Invocation`, `Diagnostics`, `Storage`, and `RpcSchedulerService` expose invocation capabilities. Database and scheduler access still require the appropriate middleware.

Use `Effect.tryPromise` when converting a fallible Promise operation to an Effect failure. `Effect.promise` turns a rejected Promise into a defect, which Loom redacts. Declare errors with `.errors(...)` when their payload belongs in the public API. Unexpected failures do not expose server details.

Await database, scheduler, and storage operations. Invocation-owned work is drained before completion; escaped capabilities reject after the invocation ends. Cancellation waits for acquired database work to settle before releasing its client. A shared runtime does not share user identity between requests.

## Replay

Explicit write idempotency keys identify one logical invocation. Authorization runs again before replay and on each transaction attempt. Reusing a key with different arguments conflicts; an incompatible saved protocol returns `RPC_VERSION_MISMATCH` instead of repeating the write. Retention is bounded, so an expired key is not an indefinite deduplication guarantee.
