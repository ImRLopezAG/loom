## Declare the contract

Every procedure has a contract under `loom/contracts/`. A file owns its route prefix: `contracts/tasks.ts` declares `tasks.*`. Use `defineContract({...})` or its callback form when you need generated validators. Native oRPC contracts carry input/output schemas, errors and metadata. Output schemas are required; input is optional.

<Snippet code={contractsSource} />

Zod and Valibot both work through Standard Schema. The contract determines client input and output types, and validates values at runtime. Declare subscriptions explicitly with `eventIterator(...)`; finite contracts stay finite.

## Configure the application

`app.config.ts` defines server environment validation and named native builders. Its `rpc` callback can return `os` and middleware-refined builders such as `auth`. Declare shared errors on a shared contract base before using them in router-wide middleware.

<Snippet code={applicationSource} />

Add `env: { STRIPE_SECRET_KEY: z.string() }` or the equivalent Valibot schema to validate server variables. Handlers receive the parsed values through `context.env`. Generation never reads secrets; deployment validates custom values, and Neon Functions startup validates its full environment including provider-injected values. Components are not implemented yet.

## Implement the router

Import named builders from `loom/_generated/rpc`. Default-export native routers below `loom/functions/`; server-only routers and their contracts belong below `loom/internal/` and `loom/contracts/internal/`. Internal routes are absent from the generated public client and public transports.

<Snippet code={functionsSource} />

Handlers receive typed `db`, `tables`, `validators`, `identity`, `env`, storage and scheduler capabilities. Generation binds schema and relations once. Use native `.handler`, `.effect`, `.use` and router composition. Generation rejects missing implementations, extra routes and implementations that do not match their declared contracts.

## Transactions and operation intent

The generated client forwards native oRPC option intent. Query, infinite, streamed and live options select read-only repeatable-read transactions. Mutation options and direct calls select serializable write transactions. Explicit iterator contracts always use read-only authority, including direct calls. Handlers run once per request; Loom does not automatically retry application code after transaction conflicts.

Client intent is untrusted and never grants permission. Authorization runs for every call, and PostgreSQL rejects writes in read-only transactions. JavaScript can still call external services; neither operation intent nor the database makes those effects safe to repeat. Streaming handlers and middleware must be safe to reevaluate.

For application handlers, the authorization callback receives `databasePolicy: "automatic"`, regardless of the client's selected options. Authorize from the verified identity, route and owned data; do not use transaction intent to relax access checks.

Output validation and serialization finish before finite database writes commit. Declare native OpenAPI metadata on contracts and set `openapi: true` in `loom.config.ts` to expose the validated REST graph. A REST request does not carry TanStack option intent; use explicit streaming contracts for subscriptions and enforce authorization independently of HTTP method.

## IDs and authorization

Use `validators.id("tasks")` or `schema.id("tasks")` to validate UUID syntax and infer `Id<"tasks">`. IDs do not prove table membership, existence or access. Check the row and ownership inside the transaction; schema references supply database foreign keys. Filter by verified issuer and subject plus your tenant policy.

## Effect and invocation lifetime

`.effect(function* (...) { ... })` uses the shared Effect runtime. Generated `Database`, `Tables` and `Validators` services preserve project types; `Invocation`, `Diagnostics`, `Storage` and `RpcSchedulerService` expose invocation capabilities. Read-only calls cannot schedule writes or create storage intents.

Use `Effect.tryPromise` for fallible Promise operations. `Effect.promise` turns a rejected Promise into a defect, which Loom redacts. Declare public errors on the contract. Await database, scheduler and storage operations: invocation-owned work drains before completion, and escaped capabilities reject after the invocation ends. Storage commits independently from application SQL.

## Replay

Explicit write idempotency keys identify one logical invocation. Authorization runs again before replay. Reusing a key with different arguments conflicts; an incompatible saved protocol returns `RPC_VERSION_MISMATCH`. Retention is bounded, and external providers need their own idempotency guarantees. See [native client options](/authoring/subscriptions) for retry and cache ownership.
