## Schema-derived boundaries

Every table exposes five Standard Schema validators under `schema.validators.<table>`:

| Validator | Purpose                                                        |
| --------- | -------------------------------------------------------------- |
| `storage` | Validate a complete stored row, including system fields.       |
| `insert`  | Accept writable fields; reject system and server-owned fields. |
| `patch`   | Accept a partial update; omission leaves a field unchanged.    |
| `command` | Accept only the table's declared `commandFields`.              |
| `public`  | Project the declared `publicFields` from a stored row.         |

The [task schema](/authoring/schemas) trims and validates titles with Valibot. The insert validator accepts a title but rejects caller-supplied ownership. The create function uses the narrower command validator, so callers cannot attach a task to an arbitrary project.

## Omission, null, and defaults

In patches, omit unchanged fields. Explicit `undefined` is rejected. `null` is a value and is accepted only by nullable fields. Database defaults are not permission to populate omitted patch fields.

Field validators may transform input, but the transformed value must still fit its storage type. Table-level `insertValidation` and `patchValidation` can enforce cross-field rules; a patch transform cannot add fields omitted by the caller.

## Function boundaries

Native contracts accept Standard Schema validators through `.input` and `.output`, including Zod, Valibot and Effect Schema. Output schemas are required; input is optional. Input validation precedes execution. Output validation and serialization finish before a finite database write commits; invalid output rolls back its writes. Iterator contracts validate every event.

Standard Schema is a boundary interface, not a nested-schema composition API. Pass generated table validators directly to `.input` or `.output`. Compose object fields using the chosen library: a Valibot ID validator cannot be placed directly inside `z.object`. When using Zod, declare its field schema (for example `z.uuid()`) and keep existence/ownership checks in the handler. OpenAPI requires a supported JSON Schema converter; Loom provides Zod and Valibot/Effect conversion and fails closed when a schema cannot be represented.

Public projections remove fields that were not selected. That is a disclosure boundary, not a record authorization policy: the handler must first decide which rows the caller can access.

## Values on the wire

The native oRPC serializer preserves Date, bigint, undefined, null, maps and sets between typed clients and procedures. Unsupported objects and cyclic values are rejected before commit. Decimal database fields remain strings. `_createdAt` is an integer epoch-millisecond value. REST clients follow the generated OpenAPI representation rather than assuming every JavaScript value is ordinary JSON.
